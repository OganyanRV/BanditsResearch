# BanditsResearch — подробное описание проекта

## 1) Контекст и предметная область
**BanditsResearch** — исследовательский проект для сравнения и валидации контекстных бандитных политик на логах показов (например, баннеры/рекомендации).

Основной фокус:
- online-like оценка (через симуляцию/последовательный прогон),
- off-policy оценка на исторических логах,
- сравнение политик между собой в едином reproducible pipeline.

## 2) Какую задачу решаем
Мы решаем задачу выбора действия (arm/action) при неизвестной награде, когда:
- есть признаки контекста (`features_list`),
- есть множество доступных кандидатов,
- награда наблюдается только для выбранного действия,
- нужно оценивать и улучшать качество политики без риска в проде.

Отсюда две инженерные цели:
1. **Обучать/обновлять** политики (разные алгоритмы и их варианты).
2. **Корректно оценивать** эти политики offline (IPS/SNIPS) и online-like (reward/regret trajectory).

## 3) Что хотели сделать (исходный замысел)
1. Убрать монолит и сделать модульную архитектуру.
2. Ввести единый интерфейс политик, включая вероятности выбора (`get_action_proba`).
3. Добавить off-policy IPS/SNIPS и пер-action аналитику.
4. Поддержать линейные, tree и custom-tree подходы в одном framework.
5. Дать удобный слой экспериментов: CLI + ноутбук + экспорт артефактов.

## 4) Что уже сделали (по проекту в целом)
### 4.1 Архитектура
Код разделён на логические модули:
- `src/bandit_benchmark_basic.py` — базовые типы/интерфейсы и простые политики;
- `src/bandit_benchmark_eval.py` — сценарии, циклы оценки, метрики, IPS/SNIPS;
- `src/bandit_benchmark_tree.py` — sklearn-tree Thompson и update/refit варианты;
- `src/bandit_benchmark_custom_tree.py` — custom-tree реализация и её политики;
- `src/bandit_benchmark_linear.py` — линейные/лапласовские/нейросетевые варианты;
- `src/bandit_benchmark_external.py` — wrapper-политики внешних библиотек;
- `src/bandit_benchmark.py` — фасад/реэкспорт публичного API.

### 4.2 Оценка и метрики
Реализованы:
- online-like метрики (reward/regret trajectories),
- off-policy функции `evaluate_policy_ips`, `run_scenarios_ips`,
- IPS/SNIPS метрики и пер-action статистика (`action_ips_stats`),
- расчёты с bootstrap для устойчивости оценок.

### 4.3 Политики и семейства алгоритмов
Поддерживаются:
- базовые: Random, Epsilon-Greedy, UCB, Thompson;
- tree-политики: sklearn-based Thompson с update/refit вариантами;
- custom-tree политики: собственный split logic и несколько режимов обновления;
- linear/neural политики (включая Laplace/encoder-based);
- external wrappers (при наличии зависимостей в окружении).

## 5) Какой функционал доступен сейчас
- Подготовка train/test и запуск benchmark-сценариев.
- Запуск нескольких политик в одном эксперименте.
- Выгрузка артефактов: `metrics.csv`, `history.csv`, `action_stats.csv`, `action_daily_stats.csv`, `action_ips_stats.csv`, off-policy/bootstrap таблицы.
- Конфигурируемые update-стратегии для tree/custom-tree политик.
- Ноутбук для интерактивного сравнения политик и гиперпараметров.

## 6) Что важно понимать про результат
Проект — это **экспериментальная платформа**, а не только один PR:
- он предназначен для быстрой проверки гипотез по стратегиям выбора действий,
- позволяет сравнивать алгоритмы в едином контуре оценки,
- и служит основой для дальнейшего переноса лучших политик в production pipeline.

## 7) Ограничения и практические замечания
- Часть политик зависит от опциональных библиотек (`scipy`, `torch`, `catboost`, `contextualbandits`).
- В offline-оценке важны корректные propensity/probability оценки (`get_action_proba`).
- IPS/SNIPS чувствительны к coverage и распределению логов, поэтому bootstrap и пер-action анализ обязательны.
